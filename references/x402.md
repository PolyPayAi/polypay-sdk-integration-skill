# x402 Agent Payments

Check the current contract at `https://polypay.ai/en/docs/x402-integration` before changing networks, schemes, or assets.

## Supported Flow

Use PolyPay x402 only for server-side paid HTTP resources. The current standard flow is `exact` with Circle USDC `transferWithAuthorization` on:

- Base: `eip155:8453`
- Ethereum: `eip155:1`
- Polygon: `eip155:137`

Do not claim current standard support for BSC, Tron, Solana, TON, or BTC. They require another scheme or a future PolyPay extension.

AI Agent Payments requires an active subscription or Pay-as-you-go access. An inactive subscription freezes resource management and verify/settle runtime access without deleting saved resources.

## Implement the Resource

1. Create the Resource in the PolyPay Dashboard with its canonical public URL, HTTP method, price, network, Circle USDC contract, settlement wallet, description, and timeout.
2. Use `@polypay/sdk/x402` in server-side JavaScript/TypeScript or the PHP SDK `x402()` helper.
3. Keep the merchant API Key in server-only secret storage.
4. On an unpaid request, return HTTP 402 with the SDK-generated requirement.
5. On a request carrying `X-PAYMENT`, verify it and settle it through PolyPay.
6. Return protected content only when settlement reports success.

The SDK and facilitator bind scheme, network, asset contract, payee, amount, resource URL, and HTTP method. They also validate the authorization window, nonce uniqueness, and EIP-712 signer.

## Handle Proxies and Retries

Pass the canonical external resource URL when a reverse proxy changes the request URL. It must exactly match the URL advertised in the requirement and configured in PolyPay.

Treat a nonce as single-use. Keep protected-content fulfillment idempotent if the client retries after a successful settlement. Do not settle before verification succeeds, and do not reveal protected data on verification or settlement failure.

## Required Tests

- No payment returns HTTP 402 and a valid requirement.
- Wrong resource, method, network, asset, amount, payee, signature, or time window fails.
- A valid Base, Ethereum, or Polygon USDC authorization settles once.
- A reused nonce cannot charge twice or fulfill twice.
- A proxy deployment matches the canonical public URL.

Use mocks and protocol test vectors for routine validation. Do not assume the normal order Sandbox simulates x402 settlement. Run a low-value production settlement smoke test only with explicit user authorization and an approved wallet.
